# REQ — 消除消息末尾偶发出现的 ACP 标签

## 问题

助手回复的**末尾偶尔**出现形如

```
Ok.

<dcp-message-id tokens="2" type="text">m00004</dcp-message-id>
```

的文本。它不只是显示问题——这段文本会**落盘到会话存储**，因此用户每次回看都能看到。

用户要求：**确定性地去掉**，不能依赖"让模型别这么写"。

## 现象与约束

- 偶发：同一会话里有的轮次有、有的没有。
- 标签里的编号往往正好等于该条消息自己的 `mNNNNN`，看起来"像是 ACP 自己加的"。
- 用户明确：**不报上游**；不重建会话。

## 验收标准

1. 新会话多轮对话后，存储里的助手文本**不再包含**该标签。
2. 不依赖模型的指令遵守（即使在提示里要求模型别输出，也必须能拦住）。
3. 非 SSE 响应、无标签的响应**逐字节不变**。
4. 现有测试全绿（仅保留既有的环境性失败）。

## 非目标

- 不改 ACP 的标签注入机制（`injectMessageIds`）——注入本身是设计的一部分，模型需要看到编号。
- 不为旧会话里已经落盘的标签做数据迁移。
